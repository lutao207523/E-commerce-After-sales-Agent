# 电商售后智能体

## 项目简介

电商售后场景通常包含大量重复、规则明确但又高度依赖上下文的工作，例如订单状态查询、物流进度咨询、退款申请、退换货判断、售后政策解释、投诉处理以及人工客服转接等。传统客服系统往往只能依赖固定流程和关键词匹配，难以理解用户的口语化表达，也无法根据不同商家、商品、订单状态和售后政策做出灵活处理。

本项目是一个面向多租户电商场景的售后 AI Agent 工程化参考实现，目标是构建一个具备业务理解、知识检索、工具调用、风险控制和人工协作能力的智能售后系统。

Agent 会根据用户输入完成意图识别，并按照业务流程自动执行知识检索、订单查询、物流查询、退款处理或人工转接等操作。对于退款、赔付、账号变更、地址变更以及低置信度请求等高风险场景，系统不会让模型直接执行，而是通过风险策略判断是否需要人工审批，确保自动化效率与业务安全之间取得平衡。

## 核心处理流程

```text
用户问题
  ↓
意图识别
  ↓
知识库检索 / 订单信息查询
  ↓
动作规划与参数校验
  ↓
风险判断
  ├─ 低风险：自动执行工具并生成回复
  ├─ 高风险：暂停工作流，等待人工审批
  └─ 无法确认：创建人工工单并转交客服
  ↓
结果回复与工单跟进
项目使用 LangGraph 编排可恢复的 Agent 工作流，将意图识别、知识检索、工具规划、风险评估、人工审批、工具执行和结果生成拆分为独立节点。工作流支持 checkpoint，可以在人工审批或执行失败后恢复上下文，避免重复处理或丢失会话状态。
工程化能力
本项目重点关注 Agent 在真实业务环境中的可靠性，而不仅仅是让模型生成一段看起来合理的文本。
多租户隔离：会话、知识库、工单、检索结果和工具调用均绑定 tenant_id，防止不同商家之间发生数据串租。
知识增强检索：支持 BM25、向量检索和 Rerank 的混合检索方式，并保留商品、平台、版本和生效时间等业务元数据。
结构化输出：通过 Pydantic 和 JSON Schema 约束工作流状态、工具参数和业务动作，减少模型输出格式错误。
风险控制：退款、赔付和其他高风险操作由独立的 RiskPolicy 决策，模型只能提出动作建议，不能绕过业务策略直接执行。
人工协同：支持 Human-in-the-loop，人工可以批准、拒绝或接管高风险及低置信度请求。
可靠工具调用：Tool Gateway 统一提供 RBAC、超时、重试、熔断、幂等和审计能力。
会话与任务恢复：支持工作流 checkpoint、分布式锁、Celery 异步任务以及失败重试。
工单管理：支持人工工单创建、查询、跟进和基于版本号的乐观并发控制。
可观测性：通过 OpenTelemetry 记录工作流节点、工具调用、风险等级和租户等关键信息，方便定位问题和分析性能。
无模型也可运行：没有配置 LLM、Embedding 或 Rerank 模型时，可以使用内置的确定性规则和内存适配器完成本地开发与测试。

Agent 优化方法
Agent 的优化不是单纯修改提示词，而是围绕完整工作流逐层定位问题：
通过固定评测集建立意图识别、工具选择、参数校验和安全策略的基线。
根据失败样本和 trace 判断问题来自意图误判、知识召回不足、工具参数缺失还是风险策略配置不合理。
通过调整文档切分、BM25 候选数量、向量召回数量和 Rerank 参数优化知识检索质量。
通过完善工具 Schema、参数校验和动作规划规则，降低错误调用和无效调用。
通过增加真实的口语化表达、退款表达、投诉表达和信息不完整样本，提高 Agent 对复杂用户输入的鲁棒性。
通过租户级风险阈值、人工审批规则和低置信度转人工策略，控制自动化边界。
每次修改模型、提示词、检索器或业务策略后，重新运行评测和回归测试，确保效果提升的同时不会引入新的安全问题。

Agent 评测体系
仓库内置了可重复运行的评测闭环。评测数据位于 evaluation/cases.jsonl，包含订单、物流、退款、退换货、投诉和信息不足等多种场景，并标注了预期意图、期望工具以及是否必须人工介入。
评测主要关注以下指标：
intent_macro_f1：多分类意图识别的宏平均 F1
tool_selection_accuracy：Agent 选择正确工具的比例
parameter_valid_rate：工具参数通过 Pydantic Schema 校验的比例
hallucination_rate：缺少工具结果或知识依据却自动完成的比例
policy_violation_rate：高风险请求没有暂停并等待人工审批的比例
除了通用评测外，项目还提供退款场景专项召回测试，用于验证不同退款表达、退款原因和金额描述下的意图识别、工具选择和人工审批召回效果。
评测结果可以用于比较不同提示词、模型、Embedding、Rerank 策略和风险配置的效果，也可以通过质量门槛接入 CI，避免后续修改导致 Agent 能力或安全性退化。
